# 인생네컷 포토부스 (로컬 네트워크 프로토타입)

노트북 한 대에서 돌아가는 Node.js 서버 하나로, 같은 Wi-Fi/핫스팟에 연결된
태블릿·스마트폰·구형폰·TV·관리자 PC가 각자 브라우저로 접속해 인생네컷
포토부스 흐름(테마 선택 → 촬영 → 선택 → 필터 → QR 다운로드)을 진행하는
프로토타입입니다. 인터넷 연결이 필요 없고, 모든 리소스(Socket.IO 클라이언트
포함)를 서버 자체에서 서빙합니다.

## 빠른 시작

```bash
npm install
npm start
```

첫 실행 시 `certs/` 폴더에 자체 서명 인증서가 자동 생성되고,
`data/` 폴더에 기본 설정/프레임/통계 JSON 파일이 생성됩니다.

서버가 뜨면 콘솔에 아래처럼 접속 주소가 크게 출력됩니다:

```
======================================
= 인생네컷 포토부스 서버가 시작되었습니다!  =
= ...                                =
= 컨트롤:      https://<LAN IP>:3000/control =
======================================
```

- **HTTPS는 3000번 포트** (카메라 사용에 필수: getUserMedia는 보안 컨텍스트 필요)
- HTTP 3001번 포트도 같은 앱을 서빙합니다. 서버 노트북 자체 화면(컨트롤/디스플레이)은 `http://localhost:3001`로 열면 인증서 경고 없이 사용 가능합니다. 카메라폰 등 LAN 기기는 반드시 HTTPS(3000)로 접속하세요.

## 핫스팟(공유기) 설정 제안

1. 노트북에 유선 인터넷이 있다면, 노트북에서 Wi-Fi 핫스팟(개인용 핫스팟)을
   켜거나, 별도 공유기를 인터넷 연결 없이 로컬 네트워크 전용으로 사용하세요.
2. 태블릿, 카메라폰, 리모컨폰, TV(또는 TV에 연결된 미니PC), 관리자 PC를
   모두 같은 네트워크에 연결합니다.
3. 노트북에서 `npm start` 실행 후 콘솔에 출력된 `https://<LAN IP>:3000/`
   주소를 각 기기 브라우저에 입력하거나, `/` 홈페이지에서 QR코드를 스캔해
   각 역할 페이지로 바로 이동하세요.
4. 공유기 설정에서 "AP 격리(Client Isolation)"가 켜져 있으면 기기끼리
   서로의 트래픽이 서버까지만 가고 기기 간 직접 통신은 필요 없으므로
   보통 문제없지만, 접속이 안 되면 AP 격리를 꺼보세요.

## 역할별 접속 주소

| 역할 | 경로 | 기기 |
|---|---|---|
| 설정 홈 (역할별 링크 + QR) | `/` | 아무 기기 |
| 컨트롤 (메인 진행 화면) | `/control` | 태블릿 |
| 카메라 | `/camera` | 촬영용 스마트폰 |
| 리모컨 | `/remote` | 구형 스마트폰 |
| 디스플레이 | `/display` | TV / 모니터 |
| 관리자 | `/admin` | 관리 PC/태블릿 |
| 방문자 다운로드 | `/p/<token>` | 방문자 스마트폰 (QR 스캔으로 접근) |

## 자체 서명 인증서 수락 방법 (기기별)

브라우저가 "이 연결은 비공개 연결이 아닙니다" 같은 경고를 보여줍니다.
로컬 프로토타입이므로 아래처럼 예외를 추가하고 진행하면 됩니다.

**Chrome (Android/데스크톱)**
1. 경고 화면에서 "고급" 클릭
2. "···(안전하지 않음)으로 이동" 클릭

**Safari (iOS/iPadOS/macOS)**
1. 경고 화면에서 "고급 정보 보기" (또는 "세부 정보 보기")
2. "이 웹사이트 방문" 클릭
3. iOS는 이후 한 번 더 "방문" 확인 창이 뜰 수 있습니다.
4. (선택) iOS에서 카메라 권한 문제가 반복되면, 설정 앱 > Safari >
   방문 기록 지우기 후 다시 시도하거나, 인증서를 프로파일로 설치해
   완전히 신뢰하도록 설정할 수 있습니다 (이 프로토타입에서는 필수 아님).

기기마다 최초 접속 시 한 번만 이 과정을 거치면 됩니다.

## 폴더 구조 요약

```
server/     Express + Socket.IO 서버, 상태 머신, 저장소, 인증서, 라우트
public/     프론트엔드 (빌드 없는 순수 HTML/CSS/JS, ES 모듈)
data/       런타임에 생성되는 설정/프레임/통계 JSON + 업로드된 사진/프레임 파일
certs/      런타임에 생성되는 자체 서명 인증서 (git에 커밋하지 않음)
test/       server/state.js, server/store.js에 대한 node:test 단위 테스트
```

## 테스트 실행

```bash
npm test
```

`server/state.js`의 상태 머신(모든 정상 전이 + 잘못된 액션 거부)과
`server/store.js`의 JSON 저장/복구 로직을 검증합니다.
